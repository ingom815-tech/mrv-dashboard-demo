# **1. 문서 목적 및 설계 원칙**

본 대시보드는 **설비 상태를 보여주는 일반 BMS 화면이 아니다.**
에너지·탄소 감축성과를 측정하고, 산정근거를 보고하며, 검증 가능한 형태로
관리하는 MRV 업무 화면이다.

| **핵심 명제** 성과값, 신뢰도, 산정근거가 한 화면 안에서 연결되어야 한다. |

## **1.2 최우선 설계 원칙**

- 첫 화면은 10초 이내에 감축성과와 검증상태를 이해할 수 있어야 한다.

- 성과 수치 옆에는 반드시 산정기간, 단위, 데이터 상태를 표시한다.

- 실측값, 추정값, 합성데이터는 색상과 라벨만으로도 즉시 구분되어야 한다.

- 설비 KPI는 성과의 원인을 설명하는 보조정보로 사용하고 메인 화면을
  지배하지 않는다.

- 원천값은 수정하지 않으며 정제값, 계산값, 승인값을 분리하고 이력을
  남긴다.

## **1.3 금지사항**

| **피해야 할 표현**            | **이유**                          | **대체 방향**                         |
|-------------------------------|-----------------------------------|---------------------------------------|
| 속도계·게이지의 과도한 사용   | 정확한 비교와 추세 파악이 어려움  | 숫자 카드 + 비교값 + 추세선           |
| 그래프를 많이 배치한 관제화면 | MRV 결론보다 설비상태가 먼저 보임 | 기준선 대비 실제 사용량을 중심 시각화 |
| 출처 없는 절감률 단독 표시    | 검증성과로 해석하기 어려움        | 기간·기준선·데이터 품질을 함께 표시   |
| 실측값과 추정값의 혼합        | 감사추적 및 제3자 검증에 부적합   | 데이터 출처·품질코드·산정상태 분리    |

## **3.3 중심 차트 표현**

- 기본 차트는 시간축 기반의 조정 기준선과 실제 사용량 비교로 구성한다.

- 두 선의 차이를 절감영역으로 표현하되 과장된 면적효과는 피한다.

- 생산량, 외기온도, 가동시간 등 주요 보정변수는 보조축 또는 이벤트
  마커로 표시한다.

- 결측·제외·추정 구간은 점선, 음영, 상태 마커로 명확히 구분한다.

- 차트 툴팁에는 시각, 기준선, 실제값, 절감량, 품질상태를 함께 보여준다.

## **4.1 기준선·성과분석 화면**

- 상단에는 분석 대상, 기준기간, 보고기간, 모델 버전, 산정상태를 고정
  표시한다.

- 조정 전 기준선과 조정 후 기준선을 구분하여 보정의 영향을 확인할 수
  있게 한다.

- 생산량·외기·가동시간·설정값 중 실제 모델에 사용된 변수만 강조한다.

- 비일상적 조정은 사유, 적용기간, 승인자와 함께 이벤트로 표시한다.

- 모델 통계값은 전문가용 상세영역에 배치하고 메인 결론을 방해하지 않게
  한다.

## **4.3 데이터 품질 화면**

| **중요** 데이터 품질은 관리자용 숨은 기능이 아니라 MRV 결과의 신뢰도를 설명하는 핵심 화면이다. |
|------------------------------------------------------------------------------------------------|

- 수집률, 정상률, 결측률, 추정률을 기간과 태그별로 확인한다.

- 원천값은 수정하지 않고 정제값과 적용 규칙을 별도로 조회한다.

- 계측기 정확도, 교정일, 교정만료일, 사용 가능 상태를 관리한다.

- 산정 제외로 연결된 데이터 이슈는 영향받은 기간과 절감량을 함께
  표시한다.

# **5. 산정 KPI 및 상태 정의**

## **5.1 핵심 계산식**

| **항목**        | **개념식**                                | **표시 유의사항**                 |
|-----------------|-------------------------------------------|-----------------------------------|
| 냉열 생산량     | Q = 밀도 × 비열 × 유량 × 온도차           | 단위환산과 센서 위치를 명시       |
| COP             | 생산된 냉열량 ÷ 투입에너지                | 본체만인지 보조동력 포함인지 구분 |
| 에너지 절감량   | 조정 기준선 에너지 − 보고기간 실제 에너지 | 음수일 경우 증가량으로 표현       |
| 온실가스 감축량 | 에너지원별 절감량 × 적용 배출계수         | 배출계수 출처·버전·유효기간 표시  |
| 비용 절감       | 사용량 절감 + 피크·요금효과               | 확정요금과 가정단가 구분          |

## **5.2 데이터 상태코드**

| **코드**  | **의미**                    | **화면 표현**         | **MRV 산정**               |
|-----------|-----------------------------|-----------------------|----------------------------|
| VALID     | 정상 수집·검증된 값         | 기본색                | 포함                       |
| MISSING   | 값이 수집되지 않음          | 회색 공백/점선        | 원칙적 제외                |
| OUTLIER   | 허용범위 또는 물리관계 이탈 | 주황 경고             | 검토 후 결정               |
| ESTIMATED | 보간·추정으로 생성          | 파란 점선 + 추정 라벨 | 승인 규칙에 따라 제한 포함 |
| MANUAL    | 수기 입력 또는 보정         | 사용자 아이콘 + 이력  | 승인 후 포함               |
| SYNTHETIC | 테스트용 합성값             | 보라색 데모 라벨      | 공식 산정 제외             |
| INVALID   | 오류 또는 사용 불가         | 빨간 제외 표시        | 제외                       |

## **5.3 MRV 업무상태**

| **상태**    | **의미**                        | **허용 작업**              |
|-------------|---------------------------------|----------------------------|
| 산정 중     | 데이터 수집·정제 또는 계산 진행 | 담당자 수정 가능           |
| 검토 필요   | 이슈 또는 비일상적 조정 존재    | 검토의견·근거 등록         |
| 검토 완료   | 산정자 검토가 끝난 상태         | 승인 요청 가능             |
| 승인 완료   | 보고 가능한 확정 버전           | 변경 시 새 버전 생성       |
| 재산정 필요 | 데이터·모델·배출계수 변경       | 기존 확정본 보존 후 재산정 |

# **6. 합성데이터 기반 데모 구축 지시**

| **적용 원칙** 합성데이터는 화면·계산·부하·예외처리 검증에 사용할 수 있으나 공식 MRV 성과와 제3자 검증 근거로 사용할 수 없다. |
|------------------------------------------------------------------------------------------------------------------------------|

## **6.1 권장 데모 범위**

| **구분**      | **권장 사양**                        |
|---------------|--------------------------------------|
| 대상          | 냉동기 1~3대, 펌프, 냉각탑, 선택 AHU |
| 기간          | 최소 1년                             |
| 수집주기      | 15분 기본, 핵심 설비 5분 선택        |
| 태그 수       | 약 30~50개                           |
| 연간 데이터량 | 5분 × 50태그 기준 약 526만 포인트    |
| 비교 시나리오 | 개선 전 기준기간 + 개선 후 보고기간  |

## **6.2 데이터 생성 규칙**

- 전력, 유량, 입·출구 온도와 COP가 물리적으로 일관되어야 한다.

- 외기온도·습도, 생산량, 가동시간이 부하와 에너지 사용량에 영향을 주도록
  생성한다.

- 정상운전 외에 부분부하, 피크, 정지·재가동, 효율저하 시나리오를
  포함한다.

- 결측, 통신장애, 센서 고정값, 급격한 이상치, 교정만료 상황을 의도적으로
  포함한다.

- 개선효과 비율은 데모 가정값으로 관리하고 실제 기대성과로 표현하지
  않는다.

## **6.3 합성데이터 표시 규칙**

- 모든 레코드에 data_origin = SYNTHETIC 값을 저장한다.

- 상단에 ‘DEMO / 합성데이터’ 고정 배지를 표시한다.

- 운영 데이터와 별도 환경 또는 별도 스키마로 관리한다.

- 생성 시나리오, 공식, 가정, 생성버전과 생성일시를 보관한다.

- 보고서와 다운로드 파일에도 ‘공식 MRV 사용 불가’를 반복 표기한다.

# **7. 시각 디자인 시스템**

## **7.1 디자인 방향**

**키워드:** 신뢰성 · 정밀함 · 투명성 · 현장성 · 검증 가능성

- 화이트 배경과 다크 네이비를 기본으로 하며 여백을 충분히 확보한다.

- 청록색은 감축성과와 정상상태, 파란색은 기준선·정보, 주황색은 검토
  필요에 사용한다.

- 장식적 그라데이션, 발광효과, 과도한 그림자와 반짝임은 사용하지 않는다.

- 카드 수를 최소화하고 정보 그룹은 정렬·간격·배경 차이로 구분한다.

## **7.2 권장 색상**

| **색상**          | **HEX**  | **사용 범위**            |
|-------------------|----------|--------------------------|
| **Dark Navy**     | \#122B4D | 헤더·핵심 제목·확정 상태 |
| **MRV Blue**      | \#1E63C6 | 기준선·링크·정보         |
| **Verified Teal** | \#159F9E | 감축성과·정상·검증완료   |
| **Review Orange** | \#C77A1A | 검토 필요·추정·주의      |
| **Risk Red**      | \#B33B3B | 오류·산정 제외·연계 실패 |
| **Surface Gray**  | \#F4F6F8 | 구역 배경·보조 정보      |

## **7.3 타이포그래피와 밀도**

| **요소**    | **권장 크기** | **규칙**                       |
|-------------|---------------|--------------------------------|
| 페이지 제목 | 24~30 px      | 한 줄 원칙, 핵심 결론형 제목   |
| 섹션 제목   | 18~22 px      | 정보 위계를 명확히 분리        |
| KPI 숫자    | 28~40 px      | 단위와 기간을 바로 인접 표시   |
| 본문·표     | 13~16 px      | 최소 크기 이하로 축소하지 않음 |
| 상태 라벨   | 12~14 px      | 색상만이 아니라 텍스트 병기    |

## **7.4 차트 규칙**

- 막대·선·영역 차트를 우선 사용하고 3D 차트는 사용하지 않는다.

- 기준선과 실제값의 색상은 전 화면에서 동일하게 유지한다.

- 축의 단위와 집계주기를 명시하고 0 기준 왜곡을 피한다.

- 범례는 가능한 차트 가까이에 직접 라벨링한다.

- 색상 외에도 선 종류, 마커, 패턴을 함께 사용해 접근성을 확보한다.

# **8. UX·데이터 연계·보안 지시**

## **8.1 상호작용 원칙**

- 요약 → 원인 → 원천데이터 순서로 단계적으로 상세화한다.

- KPI 또는 차트를 선택하면 동일 기간·설비 필터를 유지한 채 상세화면으로
  이동한다.

- 필터 변경 시 산정대상과 단위 변화가 화면에 즉시 반영되어야 한다.

- 보고서에 포함되는 화면에는 현재 필터, 산정버전, 생성시각을 표시한다.

- 오류메시지는 기술코드보다 영향범위와 조치방법을 먼저 설명한다.

## **8.2 데이터 흐름**

| **단계**      | **처리내용**                                 | **통제 기준**                          |
|---------------|----------------------------------------------|----------------------------------------|
| 1\. 수집      | BECON·PLC·BMS·독립계측·생산·기상 데이터 수집 | Read-Only, 시간동기화, Store & Forward |
| 2\. 원천보관  | 수신값을 변경 없이 저장                      | 수신시각, 출처, 품질코드, 체크섬       |
| 3\. 품질처리  | 결측·이상치·단위·교정상태 확인               | 정제규칙 버전과 처리이력               |
| 4\. 기준선    | 생산·외기·가동조건을 반영한 조정             | 모델·변수·학습기간·통계값 버전관리     |
| 5\. 성과산정  | 에너지·탄소·비용 절감량 계산                 | 계산식·배출계수·제외조건 기록          |
| 6\. 보고·승인 | 검토·승인·보고서·증적 관리                   | 변경불가 확정본과 감사추적             |

## **8.3 데이터베이스 핵심 영역**

| **영역**  | **대표 객체**                                   | **필수 관리사항**                  |
|-----------|-------------------------------------------------|------------------------------------|
| 설비·계측 | site, asset, meter, sensor, tag                 | 계층, 단위, 위치, 정확도, 수집주기 |
| 원천·정제 | telemetry_raw, telemetry_validated              | 원천불변, 품질코드, 규칙버전       |
| 조건변수  | production, operation, weather                  | 생산량, SKU, 가동시간, 외기        |
| MRV 산정  | baseline_model, calculation_run, savings_result | 모델버전, 입력범위, 결과상태       |
| 탄소환산  | emission_factor, ghg_result                     | 출처, 기준연도, 유효기간           |
| 검증·감사 | approval, audit_log, evidence_file              | 변경자, 승인자, 시각, 근거파일     |

## **8.4 보안 원칙**

- 초기 현장 연계는 읽기 전용으로 구성하고 제어·쓰기 권한은 별도
  승인한다.

- OT와 IT 네트워크를 물리적 또는 논리적으로 분리한다.

- 사용자·역할별 권한을 적용하고 다운로드·승인·기준변경을 분리한다.

- 전송구간 암호화, 백업, 접속로그, 변경로그를 운영한다.

- 감축량 확정은 승인된 규칙과 권한 있는 담당자의 절차를 거친다.

# **9. 개발·디자인 검수 기준**

| **완료 정의** 화면이 구현되었다는 사실이 아니라, MRV 결과를 이해하고 재현하고 검증할 수 있을 때 완료로 판단한다. |
|------------------------------------------------------------------------------------------------------------------|

## **9.1 화면 검수**

- 메인 화면에서 감축량, 절감률, 탄소감축량, 데이터 신뢰도, 승인상태가
  즉시 보인다.

- 조정 기준선과 실제 사용량의 차이가 하나의 중심 차트에서 이해된다.

- 실측·추정·수기·합성 데이터가 명확히 구분된다.

- 모바일보다는 데스크톱 업무화면을 우선하되 최소 1366 px 환경에서 정보가
  잘리지 않는다.

- 색상 없이도 상태와 의미를 구분할 수 있다.

## **9.2 MRV 기능 검수**

- 성과값에서 적용 모델, 보정변수, 원천데이터와 증적자료까지 추적할 수
  있다.

- 기준선·배출계수·계산규칙 변경 시 기존 확정 결과가 보존되고 새 버전이
  생성된다.

- 결측·이상치·비일상적 조정이 산정결과에 미치는 영향을 확인할 수 있다.

- 승인 완료 결과는 일반 사용자가 수정할 수 없다.

- 공식 보고서에 산정기간, 단위, 기준선, 실제값, 데이터 상태, 버전이
  포함된다.

## **9.3 합성데이터 검수**

- 합성데이터가 실제 운영 데이터와 저장·표시 수준에서 분리되어 있다.

- COP, 유량, 온도차, 전력 등 주요 변수의 물리적 관계가 유지된다.

- 정상·이상·결측·통신장애·효율저하 시나리오가 모두 포함된다.

- 데모 화면과 출력물에 합성데이터임을 숨길 수 없도록 고정 표시한다.

## **9.4 우선 구현 순서**

1.  중앙 냉수플랜트 1개 경계와 핵심 태그를 정의한다.

2.  합성데이터로 수집·품질·기준선·성과산정 흐름을 완성한다.

3.  종합 성과, 기준선 분석, 데이터 품질 화면을 우선 구현한다.

4.  현장 사전진단 후 실제 포인트리스트와 통신방식으로 교체한다.

5.  실측데이터로 기준선 모델을 재수립하고 검토·승인 절차를 적용한다.
