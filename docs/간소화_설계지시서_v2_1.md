[Heading3] 2.2.1 화면 문구 작성 원칙
화면 제목은 분석 기능명이 아니라 사용자가 확인할 결과를 표현한다.
핵심 요약은 ‘기준선 대비 무엇을 얼마나 줄였는지’ 한 문장으로 작성한다.
모델명·공식·코드값은 첫 화면 문구에 넣지 않고 산정근거에서 제공한다.
단위는 숫자 바로 옆에 작게 배치하고, 동일 화면에서는 한 가지 단위 체계를 유지한다.
상태 문구는 ‘정상·검토 필요·승인 완료’처럼 행동 판단이 가능한 표현을 사용한다.
[Heading1] 2.3 시각 디자인 레퍼런스
아래 이미지는 화면 내용이나 색상을 복제하기 위한 예시가 아니다. 넓은 여백, 둥근 카드, 큰 핵심 숫자, 단순한 메뉴 구조와 같은 시각적 분위기를 참고한다.
디자인 레퍼런스 — 구성·여백·카드 표현만 참고하며, 예시의 로고·수치·서비스 구성은 사용하지 않는다.
채택 방향  3·4번의 밝고 정돈된 SaaS 구조를 중심으로 적용하고, 1번은 강한 정보 위계만 참고한다. 2번처럼 많은 차트와 카드를 한 화면에 배치하지 않는다.

[Heading2] 2.6 화면 스타일 적용 지시
좌측 메뉴는 현재의 넓은 회색 패널보다 가볍고 좁게 표현한다. 메뉴 설명문은 숨기고 선택 상태만 명확히 표시한다.
페이지 제목과 보고기간 선택은 같은 행에 두고, 우측에는 ‘보고서’ 또는 ‘산정근거’ 버튼 하나만 둔다.
KPI 카드 3개는 동일한 높이와 여백을 사용하며, 숫자와 단위 사이의 위계를 분명히 한다.
메인 차트는 화면에서 가장 큰 카드로 두고, 오른쪽 신뢰도 요약 카드는 차트 높이와 맞춘다.
보라색 전체 배경, 원색 KPI 카드 여러 개, 큰 원형 게이지, 인물 아바타와 제품 이미지는 사용하지 않는다.

[Heading2] 4.1 상세 화면 열기 방식
KPI 카드를 클릭하면 해당 상세 화면으로 이동한다.
‘산정근거 보기’는 오른쪽 슬라이드 패널로 먼저 열고, 전체 상세로 확장할 수 있게 한다.
검토 필요 항목은 메인에 긴 목록을 두지 않고 건수와 가장 중요한 1건만 표시한다.
차트의 특정 월을 클릭하면 해당 월의 데이터 이슈와 설비 원인을 연결한다.
사용자가 상세 화면에서 돌아와도 보고기간과 필터 선택을 유지한다.
[Heading2] 4.2 합성데이터 표시
데모 표기  화면 최상단 전체 배너 대신 페이지 제목 옆에 ‘DEMO · 합성데이터’ 배지 하나를 고정한다.
합성데이터 여부는 숨길 수 없어야 한다.
경고 문구 전체를 반복 노출하지 않고 배지의 툴팁에서 상세 설명을 제공한다.
[Heading1] 5. 개발 검수 기준
1440×900 화면에서 핵심 KPI 3개와 중심 차트가 스크롤 없이 보인다.
첫 화면의 독립 카드 또는 박스는 7개를 넘지 않는다.
메인 차트에 기본 표시되는 선은 2개를 넘지 않는다.
화면 내 긴 목록은 없으며 검토 항목은 1건 미리보기만 제공한다.
모델 공식과 기술 통계값은 종합성과 화면에 노출하지 않는다.
사용자 5명 대상 테스트에서 5초 안에 절감량·탄소·검증상태를 찾을 수 있어야 한다.
각 핵심 수치에서 산정근거 또는 관련 상세 화면까지 2회 클릭 이내로 이동한다.
[Heading2] 5.1 구현 우선순위
종합성과 화면에서 상세 표·목록·기술정보 영역을 제거한다.
KPI를 3개로 통합하고 제목과 요약 문장을 단순화한다.
기준선·실제 사용량 중심 차트와 신뢰도 요약만 남긴다.
제거된 기능을 성과분석과 데이터·검증 메뉴로 이동한다.
1366 px 및 1440 px 환경에서 가독성 검수를 진행한다.
최종 판단 기준  첫 화면이 ‘전문가만 이해하는 검증 콘솔’이 아니라 ‘누구나 결론을 이해하고 필요할 때 근거를 확인하는 MRV 성과 화면’으로 보여야 한다.
